SYSTEM_RULES_ENFORCEMENT:

1. COMPONENT_STRUCTURE_TRIAD (STRICT):
Every component resides in `src/components/[folderName]/` or `src/pages/[folderName]/`.
A folder named `[folderName]` (camelCase) MUST contain:
- component.jsx: Pure UI structure. Only imports logic and styles.
- style.css: Local styles using BEM-Aotopo convention.
- use[FolderName].js: Mandatory logic isolation (State, Effects, Events, Logic).
- readme.md: Component documentation.

2. FILE_NAMING_PROTOCOLS:
- Folders: Always `camelCase`. Never use hyphens, underscores, or spaces.
- UI Entry: Always named `component.jsx`. Never use [Name].jsx or index.jsx.
- Logic Hooks: Named `use[Name].js` or `[logicPurpose].js`.
- Style: Always `style.css`.

3. LOGIC_SEPARATION_MANDATE:
- JS logic inside JSX is forbidden (except for simple mapping or conditional rendering).
- Use custom hooks for scroll, resize, click, business rules, and state management.
- The `component.jsx` file must be declarative and clean.

4. STYLING_SYNTAX (BEM-AOTOPO):
- Class naming: `[folderName]__[elementCamelCase]`.
- Modifiers: `[folderName]__[element]--[modifierCamelCase]`.
- NO TAILWIND. NO UTILITY CLASSES. NO INLINE STYLES for static layout.
- Inline styles are permitted ONLY for runtime calculations (e.g., dynamic progress bars, position offsets).
- Global variables in `src/styles/root.css` and `global.css` must be prioritized.

5. ARCHITECTURE_NAVIGATION:
- Assets: Shared assets in `src/assets/`. Component-specific assets in `src/components/[name]/assets/`.
- Pages: Complex layouts in `src/pages/[pageName]/` following the same component triad.
- Global Styles: Managed in `src/styles/`.
